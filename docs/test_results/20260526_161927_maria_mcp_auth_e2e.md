### [1] 정상 키 — `X-API-Key: test-key-abc`

```bash
curl -s -i -X POST http://localhost:8001/mcp \
  -H "X-API-Key: test-key-abc" \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'
```

응답:
```
HTTP/1.1 400 Bad Request
mcp-session-id: e6feac57f60741f29d1fd9afbaf2e708
{"jsonrpc":"2.0","id":"server-error","error":{"code":-32600,"message":"Bad Request: Missing session ID"}}
```

판정: **✅ 인증 통과** — 400 은 MCP 프로토콜 단계 에러(세션 ID 미포함). 인증 미들웨어는 통과한 뒤 MCP streamable HTTP 핸들러까지 도달했음을 의미.

## 4. 부수 발견 사항 — `.env` 의 `MCP_API_KEY` 빈 문자열

1차 시도에서 세 케이스 모두 400 만 반환되고 401 이 나오지 않음. 원인 추적:

- `.env` 의 `MCP_API_KEY=` 값이 빈 문자열로 설정됨 (`awk -F= '/^MCP_API_KEY=/{print length($2)}' .env` → `0`)
- `server.py:245` 의 `if s.mcp_api_key:` 가드가 False → `_ApiKeyMiddleware` 자체가 미등록
- 기동 로그(line 미포함, 1차 기동분에서 확인됨):
  ```
  WARNING maria_mcp.auth - MCP_API_KEY 미설정 — API Key 인증이 비활성화되었습니다 (개발 모드).
  운영 배포 전 반드시 환경변수 MCP_API_KEY 를 설정하세요.
  ```

→ 환경변수로 키를 명시 주입(`MCP_API_KEY=test-key-abc uv run maria-mcp`)한 뒤 재기동하여 본 검증 수행.

**권고**: 운영 서버(`1.234.33.214`) 측 `.env` 의 `MCP_API_KEY` 도 동일하게 빈 문자열인지 확인 필요. 빈 값이면 인증 OFF 상태로 운영 중인 것이므로 즉시 키 설정 권장.
