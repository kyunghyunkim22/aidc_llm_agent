# implement — 7단계 구현 워크플로

신규 구현 요청을 받았을 때, 메인이 즉시 코드를 짜는 대신
아래 7단계를 **순서대로** 수행한다. 각 단계의 산출물이 누락되면 다음 단계로 진행하지 않는다.

## 0. 사용 전 판단

이 스킬을 적용해야 하는 작업인지 먼저 판단한다.

**적용 O**
- 신규 함수·MCP tool·모듈·엔드포인트 추가
- 기존 함수의 시그니처·동작 변경 (50줄 이상)
- 새 외부 의존(DB 테이블, API) 추가

**적용 X**
- 1~2줄 버그 수정
- 오타·포맷팅
- import 정리
- 기존 함수 시그니처 유지 + 테스트 없는 리팩터 (사용자가 명시적으로 "TDD로" 요청한 경우 제외)

판단이 애매하면 사용자 확인 없이 적용한다 (CLAUDE.md "확인 질문 없이 바로 실행" 우선).

## 1. 스펙 확인 — `spec-reader`

- 관련 spec 문서(`docs/spec/<module>_spec.md`) 분석
- 구현 체크리스트 추출
- 모호점·TBD 식별
- spec이 없으면 작업 중단 후 사용자에게 spec 작성 여부 확인

**산출물**: 구조화된 요구사항 리스트 + 모호점 보고

## 2. 테스트 작성 (Red) — `test-writer`

- 정상 케이스 1개
- 빈 결과 케이스 1개
- DB/외부 의존 실패 케이스 1개
- timeout/취소 케이스 1개
- 잘못된 입력 케이스 1개
- **최소 5케이스**, 모두 **실패 상태**로 작성 (구현이 없으므로 당연히 fail)

**산출물**: `tests/test_<module>_<func>.py` (단위 테스트)

## 3. 구현 (Green) — `implementer`

- 2단계 테스트를 통과시키는 **최소** 코드
- spec 의 요구사항 누락 없이
- async/타입힌트/파라미터화 SQL/환경변수 시크릿 규칙 준수
- 추측성 추상화·확장 포인트 금지 (CLAUDE.md 핵심 설계 원칙)

**산출물**: 구현 코드 + 단위 테스트 PASS 결과

## 4. 통합 테스트 — `test-writer`

- 실 MariaDB/Qdrant/Druid/외부 API 접속 테스트
- `.env` 의 실 접속정보 사용 (모킹 금지)
- 기존 `tests/test_<module>_integration.py` 에 추가

**산출물**: 통합 테스트 PASS

## 5. 전체 회귀 — 직접 실행

```bash
uv run pytest tests/
```

- 신규 변경으로 기존 테스트가 깨지지 않았는지 확인
- 실패 시 3·4단계로 회귀하여 수정

**산출물**: 전체 PASS 로그

## 6. 코드 리뷰 — `code-reviewer`

다음 체크포인트 검증:
- async/await 누락
- 타입힌트 누락
- SQL 파라미터화 (f-string SQL 금지)
- 환경변수 시크릿 (하드코딩 금지)
- 에러 처리 (boundary 만, 내부 트러스트)
- 로깅 (`log_tool_call` 등 컨벤션)
- 불필요한 추상화·확장 포인트 (CLAUDE.md 단순성 우선)

**산출물**: 리뷰 코멘트 + 수정 사항 (있으면 3단계로 회귀)

## 7. 설계 검증 — `design-validator`

- spec 문서 vs 구현 코드 정합성
- CLAUDE.md 의 모듈 상태표 vs 실제 상태
- 다이어그램(`docs/diagrams/`) 과의 흐름 일치
- 설계 드리프트 발견 시 [CONFLICT] 보고 (임의 동기화 금지)

**산출물**: 정합성 보고서

## 완료 보고

각 단계 산출물 위치 + 회귀 테스트 결과 + 사용자에게 다음을 한 번에 회신:

```
## implement 완료
- spec: <분석 결과 위치>
- 테스트: tests/test_xxx.py (N케이스 PASS)
- 구현: src/xxx.py
- 통합: tests/test_xxx_integration.py (PASS)
- 회귀: <PASS/FAIL>
- 리뷰: <PASS/issues>
- 설계검증: <PASS/CONFLICT>
```

## 예외·단축 지시

사용자가 워크플로 진행 중 **"스킵 N"**, **"N단계 빼"**, **"리뷰만"** 등으로
특정 단계 생략을 명시하면 그 단계만 건너뛴다. 단, 1·6·7 단계는 가능한 한 유지.

작업 도중 사용자가 **"중단"** 또는 **"여기까지"** 라고 하면 현재 단계 산출물만 저장하고 종료.
